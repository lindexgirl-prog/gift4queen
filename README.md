# «50 моментов, за которые я тебя люблю»

Мобильный цифровой семейный архив на React, TypeScript и Vite. Тексты, порядок карточек и пути к медиа находятся в одном файле `src/data/archive.json`; фотографии, аудио и видео лежат отдельно в `public`.

Все 50 основных карточек подтверждены для первой публичной версии. В них подключены 50 реальных фотографий из пользовательской папки «под» и написаны связанные с кадрами тёплые послания.

## Быстрый запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Vite покажет локальный адрес, обычно `http://localhost:5173`.

Основные страницы:

- `/` — последовательная история;
- `/moments` — фотографии, видео и голоса только из уже просмотренных карточек;
- `/edit` — скрытый локальный редактор.

## Где что хранится

```text
public/
  images/       фотографии и обложки видео; текущие 50 кадров лежат в family-archive/
  audio/        голосовые сообщения MP3
  video/        короткие видео MP4
src/
  archive/      прогресс просмотра
  components/   интерфейс архива и редактора
  data/
    archive.json       все тексты, главы, карточки и пути к медиа
    archiveSchema.ts   правила проверки данных
  editor/       операции добавления и сортировки
scripts/
  validate-content.ts проверка архива перед публикацией
```

Не добавляйте личные тексты внутрь React-компонентов. Источник контента — только `src/data/archive.json`.

## Текущий набор из 50 фотографий

- сайт использует файлы `public/images/family-archive/memory-01.jpg` … `memory-50.jpg`;
- №1 — самый ранний чёрно-белый снимок, №50 — совместный взрослый портрет;
- внутри история идёт через детство, школьные годы, известные даты 2018–2023 годов, поездку, времена года и новое поколение семьи;
- соответствие карточек исходным именам записано в `outputs/desktop-photo-selection-50.json`;
- общий лист всех кадров в порядке показа находится в `outputs/desktop-photo-order-contact-sheet.jpg`;
- прежний набор сохранён в `outputs/previous-vk-family-archive` и в `outputs/vk-family-archive-50.zip`.

Исходную папку на рабочем столе сайт не читает. После копирования фотографии можно менять только в `public/images/family-archive`, не затрагивая оригиналы.

## Как редактировать архив

1. Откройте `/edit`.
2. Выберите главу или карточку.
3. Измените нужные поля. Черновик автоматически сохраняется в этом браузере.
4. Для голосов, дополнительных фото, видео, маршрута и эффектов откройте блок «Все поля карточки».
5. Нажмите «Экспортировать JSON».
6. Замените экспортированным файлом `src/data/archive.json`.

Редактор не загружает файлы на сервер. Автосохранение хранится только в `localStorage`; для переноса между компьютерами используйте экспорт и импорт JSON.

Если обязательное поле временно осталось пустым, редактор всё равно восстановит такой локальный черновик после перезагрузки и покажет предупреждение. Строгая проверка сработает при экспорте и не даст опубликовать незавершённые данные.

## Как заменить основную фотографию

1. Положите файл, например, в `public/images/card-01.jpg`.
2. В `/edit` укажите путь `/images/card-01.jpg`.
3. Обязательно заполните `alt` — короткое точное описание того, что изображено.
4. Экспортируйте обновлённый JSON.

Рекомендуется использовать понятные имена без пробелов: `card-01.jpg`, `trip-2027-01.jpg`, `card-12-poster.jpg`.

## Как добавить дополнительное фото или видео

В полном JSON выбранной карточки добавьте объект в `extraMedia`.

Дополнительная фотография:

```json
{
  "type": "image",
  "src": "/images/card-01-extra-01.jpg",
  "alt": "Описание фотографии",
  "caption": "Необязательная подпись"
}
```

Короткое видео:

```json
{
  "type": "video",
  "src": "/video/card-01.mp4",
  "poster": "/images/card-01-poster.jpg",
  "caption": "Подпись к видео",
  "transcript": "Полная текстовая расшифровка"
}
```

Видео должно быть MP4 с H.264/AAC и весить не больше 25 MiB. Автовоспроизведения нет. Для каждого видео обязательны постер, подпись и расшифровка.

## Как добавить голосовое сообщение

1. Запишите настоящий голос пользователя и сохраните файл как MP3 в `public/audio`.
2. Не используйте синтез голоса от имени пользователя.
3. В полном JSON карточки заполните `voiceMessage`:

```json
{
  "enabled": true,
  "audio": "/audio/card-01.mp3",
  "title": "Послушать мои слова",
  "dedication": "От меня — тебе",
  "transcript": "Полная расшифровка записи"
}
```

Для карточки №50 используйте название «Даже когда я стану взрослым» и кнопку «Послушай это, когда закончишь».

Плеер запускается только вручную, поддерживает клавиатуру, показывает прогресс и работает без Web Audio API. Если файл не открылся, интерфейс выводит понятное сообщение.

## Как добавить главу или карточку

Проще всего сделать это в `/edit` кнопками «Добавить главу» и «Добавить карточку». Порядок меняется стрелками.

Важные правила:

- `id` — постоянный идентификатор. После публикации не меняйте его без необходимости: по нему хранится прогресс просмотра;
- `number` — номер на карточке;
- `order` — положение внутри главы;
- неизвестные `year`, `dateLabel`, `location` и `emotion` можно удалить — пустые подписи не показываются;
- перед публикацией у карточек №1–50 должен быть статус `ready`;
- карточки №52 и далее можно добавлять в существующую или новую главу без изменений компонентов.

## Карточка №51

`memory-051` открывается только после просмотра №50 и нажатия «Перевернуть последнюю страницу». Пока `futureSlot.image` равен `null`, показывается пустая Polaroid-рамка.

Чтобы превратить её в настоящее воспоминание, добавьте изображение:

```json
"futureSlot": {
  "label": "Наше новое воспоминание",
  "image": {
    "type": "image",
    "src": "/images/memory-051.jpg",
    "alt": "Описание нового семейного снимка"
  }
}
```

## Маршрут путешествия и эффекты

Локальная карта не обращается к внешним сервисам и не передаёт координаты третьим сторонам.

```json
"route": {
  "label": "Маршрут нашей поездки",
  "points": [
    { "x": 16, "y": 68, "label": "Начало" },
    { "x": 78, "y": 30, "label": "Финал" }
  ]
}
```

Допустимые эффекты: `vintage-photo` и `soft-particles`.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run test:node
npm run build:preview
npm run build:pages
```

`npm run build:preview` проверяет код и собирает локальное превью с черновиками. Для реальной публикации используется строгая команда:

```bash
npm run build:release
```

Она завершится ошибкой, если:

- не все 50 основных карточек имеют статус `ready`;
- JSON нарушает схему, содержит повторяющиеся ID/порядок или неизвестные главы;
- обязательные `alt` и расшифровки отсутствуют;
- указанный медиафайл не найден;
- путь пытается выйти за пределы `public`;
- MP4 превышает 25 MiB.

Обычная команда `npm run build` также является строгой и эквивалентна релизной проверке.

## Подготовка к публикации

1. Проверьте даты, места и соответствие каждой истории фотографии.
2. Добавьте реальные MP3/MP4 и расшифровки, если они появятся.
3. Выполните все команды из раздела «Проверки», включая `npm run build:pages`.
4. Проверьте архив на телефоне и компьютере, вручную пройдите карточки №1–51.
5. Отправьте подтверждённое состояние в ветку `main` на GitHub. Workflow `.github/workflows/deploy-pages.yml` проверит проект и опубликует только `dist/client`.
6. В настройках GitHub Pages укажите домен `gift4queen.ru`, а у регистратора направьте домен на GitHub Pages.

`npm run build:pages` дополнительно создаёт `404.html` для прямого открытия `/moments` и `/edit`, а также файл `CNAME` для домена. GitHub Pages является публичным хостингом: фотографии доступны всем, кто знает адрес.

## Ограничения первого релиза

- backend и база данных отсутствуют;
- прогресс хранится только на текущем устройстве в `localStorage`;
- редактор не загружает файлы и не меняет опубликованный сайт;
- после изменения JSON или медиа нужна новая сборка и публикация;
- печатные карточки и QR-макеты остаются отдельным будущим этапом.
